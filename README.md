# 织造工作坊口述稿与工位交接

带教老师使用各师傅的技法资料和试样记录安排工位。
演练资料使用虚构单位、人员与业务文字。资料以 UTF-8 JSON 给出，各文件按收到的顺序保存，正文中引述的名字和词形按原样保留。

## 资料格式

每份资料是记录数组。编号的作用范围是所在资料集，同一业务对象如有不同版本则另列记录。空字符串表示交接文件未填写，空数组表示未列条目。没填写的值无法代替明确的反面事实。

- `data/manuscripts.json` 保存id、版本、师傅、来源、内容。同一段的新录音稿用上升版本号，保留原稿。

- `data/stock.json` 保存id、工位、资源、数量、里侧、时段。器具和材料的库存以一次工作坊为准，里侧为能否离开工位借用。

- `data/learners.json` 保存id、学员、可做、需老师、时段。由带教老师给出的工序资格和可到时段。

- `data/samples.json` 保存id、学员、状态、台位、特征、本次要求、原始指令。已做记录来自工位交接，原始指令可为空。

- `data/directions.json` 保存id、文稿、版本、状态、说明。带教老师既有领用及工位指示，说明为原话。

- `data/handoff.json` 保存id、来自、到达、适用、文字。师傅交接单中的用语和已经存在的器具限制。

## 试样说明编制器

`workshop` 包在不改写原稿的前提下，把结构化解析、教师确认和现场状态编成学员本次可执行的试样说明。

- `data/parses.json` 是原稿的结构化解析层：每一步登记原句、操作、补全的宾语、承接前指、是否可选、重复次数、前置条件、效果特征、需用资源、工位与离台前整理。同一词形在不同稿版本中的所指登记在“术语表”，例如“回穿两道”在 W1 指经面回穿（同一层经线），在 W2 指边线回穿（上一道未收的边）。
- `data/confirmations.json` 登记三类教师结论：跨版本“接续确认”（成立/不成立/待复核）、满足工序前后条件的“材料替代”、新供稿补出省略文字后的“解释复核”。计划器只接受状态为“成立”且共同接续点经求值通过的衔接；文字相似或产物同名不能衔接。
- 未做样件须由老师指定起始稿；在制样件按已形成特征定位进度，原做法做不下去时保住特征，只有剩余步骤能接上实际半成品才改领用单，否则列缺的准备并交回老师。
- 资源区分“留台/可借”、上午/下午批次和交接单预占；替代料必须同时满足替代登记的前置条件和同一工序的效果特征。
- 学员视图只保留本次支路（含重复次数、前置准备、停手条件），教师视图可从每个工序回到原句，`lookup` 可查已发说明采用的版本、确认与替代。

```text
python3 -m workshop plan S3 --时段 上午
python3 -m workshop plan S4 --时段 下午 --起始稿 W5:1
python3 -m workshop plan S1 --时段 上午 --纹样 菱 --视图 教师
python3 -m workshop trace S3 --时段 上午
python3 -m workshop lookup I2
```

## 阅读与运行

使用 Python 3.11.2 和标准库，无需安装第三方包。在仓库根目录可列出交接资料，或查看一条原始记录的所有版本。测试核查文本能原样读取、资料之间的关联，以及试样编制器的各项纪律。

```text
python3 -m corpus
python3 -m corpus manuscripts --id W1
python3 -m unittest discover -s tests -v
```
